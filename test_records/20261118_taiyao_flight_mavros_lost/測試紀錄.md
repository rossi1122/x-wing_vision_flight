## 原因：程式開始 38.7 s 後，MAVROS (飛控) 資料整個停了

| 證據 | 內容 |
|---|---|
| events | **整份沒有「★ GUIDED 上升沿」**，模式鍵送出 0 次 → 程式從來沒發現撥了 GUIDED，**沒有開始任務、沒有送任何命令** |
| 程式看到的飛控模式 | 3,087 s 全程都是 **MANUAL** |
| 飛控資料 | 姿態、空速、高度、電池、GPS **在 t = 38.66 s (約 11:47:26) 同一瞬間全部停止更新**，之後一直停在地面時的值 (AGL ≈ 0、位置不變) |
| 程式本身 | 控制迴路照常 50 Hz、雲台 UART 資料一直更新到最後 → **程式沒有當掉，只有 MAVROS 這條斷了** |

所有飛控話題同時停住 → **MAVROS 跟飛控之間的連線斷了** (MAVROS 停止 / 飛控 USB 斷線或重新列舉 / 飛控重開)。
這份 log 沒辦法確定是哪一種 (kernel 快照不是在 38.7 s 拍的)。

### 為什麼會「直接右轉」
撥 GUIDED 後飛控在等外部命令，但程式不知道 GUIDED、而且 MAVROS 斷了也送不出去
→ ArduPlane **GUIDED 沒收到命令時會在當下位置繞圈 (預設順時針 = 往右轉)**。
所以「直接右轉」不是程式下的命令，是飛控 GUIDED 的預設行為。

## 雲台 (台鴞) 的部分

- 開頭 31.6 s 沒收到雲台資料 (對方還沒開始送)，之後正常，到約 2482 s (落地後) 對方停止送。
- 傳輸：CRC / 封包錯誤 0，封包 73,524 筆 (v8)，校時 1,225 次。
- 台鴞的雲台 roll **沒有跟著飛機 roll** (空中只有 ±2~4°，降落時 −22~+15°)：跟田屋小雲台不同 (田屋小跟著機身 roll)。

## 已做的修正 (程式)

1. **飛控資料看門狗** (`xwing_vision_flight.py`)：IMU 超過 1 s 沒更新 →
   - events 記 `★★★ 飛控 (MAVROS) 資料中斷`，終端機用 `!!!!` 框起來印；之後每 30 s 再提醒；恢復時記「飛控資料恢復」
   - 狀態列最前面顯示 `★★★FC資料停 N s★★★`
   - 撥 GUIDED 時**拒絕啟動任務** (原因寫「飛控資料中斷」)
   - CSV 新增 `fc_age_s` 欄位 (飛控資料年齡)
2. 繪圖 summary：`fc_age_s` 超過 1 s 會出現 ✗。
3. `FLIGHT_DAY_QUICK.txt`：起飛前 / 撥 GUIDED 前確認狀態列 AGL / V 有在變、沒有 ★★★FC資料停；
   出現時不要撥 GUIDED，重開 MAVROS 後也要重開飛行程式。

## 建議

- 找出 MAVROS 為什麼斷：當天 Terminal 1 (MAVROS) 的畫面 / log；飛控 .BIN 在 11:47 左右有沒有重開 (會開新的 BIN 檔)；飛控 USB 線有沒有鬆。
- 建議 `roscore` 單獨開一個 terminal，MAVROS 另外開：這樣重開 MAVROS 不會把 roscore 一起關掉。
